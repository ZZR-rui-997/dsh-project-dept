# project-dept

> 一个通用的「项目部」规程：把一次复杂工作当成一个**可验收的板块**，串行推进，用开工闸门、三层验收 + 独立复核、基准自审、方向复盘来保证交付物可信。

## 它解决什么问题

多智能体（或多人）协作时，**调度**是宿主的能力，**判断对错**没人负责。结果是：
东西做出来了、看着挺像、报告说跑通了，但**没人能证明它对**，而且错得很整齐——
因为所有人都在对着同一把没验证过的尺子核对。

这个 skill 只干一件事：给「做对」建立可判定的流程与检查点。它**不**提供专业知识，
也**不**提供工具实操；那些交给项目自己的岗位卡与专门的 skill。

## 三条不可协商

1. **交付 ≠ 完成**。执行者永不自标完成；交付要过 L1 自检 → L2 独立复核 → L3 终判。
2. **独立是硬要求，不是礼貌**。复核人不得是作者、不得参与制作、不得看到作者的结论摘要。
3. **尺子本身也是嫌疑人**。任何被当基准的东西必须标出处等级；自家整理稿不能当验收基准。

## 什么时候加载

- 用户说「按项目部开工 / 开一个板块 / 组团队做这块」；
- 任务大到要拆给多人/多轮，且交付物要经得起检验；
- 用户强调「检查要独立」「别自己说了算」；
- 要在已有项目里建立或核对台账（看板 / 登记簿 / 基准清单）。

## 什么时候不加载

- 单文件小改、纯查询、改个错别字；
- 没有可判定验收标准的探索性对话；
- 需要**实时**拦截工具调用的场景（用宿主的插件/钩子机制，别用规程绕）。

  check_skill.py            包自检（8 项：frontmatter/版本/声明资产/禁名/预算/evals/完整性/manifest 语法含重复键）
  run_evals.py              eval runner（static 校验 schema；judge 生成盲判任务单；tally 配对统计；grade 已弃用）
  check_review_form.py      复核单结构校验（7 条规则：快照/判定/必改一致/独立性/证据/禁用短语/真问题）

## 质量工具（完整清单以 `manifest.yaml` 的 `quality_tools` 为准，别在这里数个数）

**`dept_gate.py`** —— 开工前、每次汇报前跑。检查台账结构、当前板块、未处置债务、
散落临时脚本、岗位卡、未溯源基准、方向复盘是否还是模板。

退出码（**仅 `dept_gate.py`**；`check_doc.py` 的 `2` 含义不同，见下）：
`0` 通过 / `1` 阻塞（结构性问题，含「找不到债务账本小节」）/ `2` 需决策（有未处置债务）/ `3` 未执行。

```bash
python scripts/dept_gate.py                 # 从 cwd 向上找 dept.config.json
python scripts/dept_gate.py --config path/to/dept.config.json
```

**`check_doc.py`** —— 交付文档前跑。八条断言：图/表/公式编号连续、图注↔正文双向、
表注↔正文双向、参考文献、章节编号连续（只认 Word 标题样式）、术语写法（禁用词表来自项目配置）。
**参考文献这条的覆盖范围要看清**：编号制（`[1]`）是**双向**核对；作者-年份制只核
「清单里的每条都被正文引用」**一个方向**，反方向（正文是否引用了清单外文献）无法机械识别，
报告里会明说"未机械核对"，不许当成双向通过。

退出码（**仅 `check_doc.py`**）：`0` = **已执行的断言**全部通过（未执行的会逐条列出，**不等于全部查过**）/
`1` 有 FAIL / `2` 未执行（主要情形，**不限于**：缺文件、缺 python-docx、缺配置或配置解析失败/类型不对、
结构性断言执行 <3 条、本目录有台账但配置只在祖先目录找到；代码里还有空文档、结构性断言不足等其它路径）。
另外两种情况**不算未执行、直接判 FAIL**：未给 `--chapter` 时，文档里确有图/表编号但一条都没被识别（编号制式不支持）；
以及**悬空引用**——判定顺序是「先全篇、后本章」：①全篇一条图注都没有而正文引用了图 ⇒ FAIL（与是否给 `--chapter` 无关）；
②**跨章悬空**：正文引用了「全篇都没有图注」的编号 ⇒ FAIL —— 按 **(章号, 编号) 二元组**比，本章引 图 9-9 不会被别章的 图 2-9 满足；省略章号的引用（「图 9」）只要任一章有同号图注就算被满足（**但注意**：在"章-号"制式的文档里出现省略章号的编号，A1 会按"混用制式"判 FAIL——要么全文统一成 章-号，要么统一成全局编号；这是有意的保守判定，不是漏判）；③给了 `--chapter N`、该章没有图注，且正文只引用了**别的章节**的图 ⇒ 记「未执行」并说明「属于其他章节，不在本章核对范围」（**不是** FAIL：别章有注、不是悬空；也**不是**"没有任何引用"）；④另一条**未执行**路径（与③并列、不是唯一情形）：该章既无图注、正文也确实没有引用任何图 ⇒ 记「未执行」。
**两个「未执行」码不同，别混读**：`dept_gate.py` 用 `3`（缺配置 / 解析失败 / 顶层不是对象 /
祖先配置污染），`check_doc.py` 没有 `3`，同类情形一律 `2`。

```bash
python scripts/check_doc.py 论文.docx --chapter 2
```

**`check_skill.py`** —— 改完 skill 包**自己**之后跑。八项静态检查：frontmatter（`name` 必须等于目录名、
`description` ≤1024）、四处版本一致（SKILL / manifest / README / README_EN）、manifest 与 SKILL 里声明的资产
真的存在（含不带扩展名的脚本写法）、入口与全包文档不得出现不随包分发的文件名、上下文预算（`SKILL.md` 超过
**3,000 tokens ⇒ 缺陷 exit 1**；`SKILL.md + always_load` 超过 9,000 只警告；**单次开工实际加载**还要加上每轴
最大片段，超过 14,000 ⇒ 缺陷、超过 9,000 警告）、`evals.json` 可读、包完整性。

```bash
python scripts/check_skill.py --root .        # 加 --json 出机器可读结果
```

退出码：`0` 无缺陷 / `1` 有缺陷 / `2` 未执行。**预算数字会随正文漂移**，以它的输出为准，别把文档里的数值当常量。

**`run_evals.py`** —— 路由或复核行为变了之后跑，也用于有效期对照（with / without 两臂）：

- `static`：校验 `evals/evals.json` 的 schema，并给每条 case 打印可直接粘给判官的评分提示；
- `judge --answers <目录> --out <目录> [--seed 7]`：把 `<case>-<arm>-r<rep>.txt` 答案**匿名化**成盲判任务单
  （A/B/C… 随机化 + 私有映射表），产出可粘贴的判分模板；
- `tally --out <judge 输出目录>`：配对统计 + 每条 rubric 分项 + Wilson 95% 区间；
- `grade`：**已弃用**——逐字关键词判分在 12 份真实答案上 12/12 假 FAIL（backlog P-15-8），**不得当验收判据**；
  `compare` 建立在 `grade` 上，只能看方向，不能当结论。

```bash
python scripts/run_evals.py --mode static
python scripts/run_evals.py --mode judge --answers path/to/answers --out path/to/judge-out
python scripts/run_evals.py --mode tally --out path/to/judge-out
```

退出码：`static` 0 通过 / 2 未执行；`judge` 0 通过 / 2 答案目录不合规或未执行；`tally` 0 通过 /
2 未执行或模板留空（缺分会逐格点名）；`grade` 0/1/2（已弃用，仅供回归）。

**`check_review_form.py`** —— 收到复核单先跑它。七条结构规则：§0 两次锚哈希快照（不一致必须写明「只对开始版有效」）、
§1 判定唯一且合法（通过 / 通过但要修 / 不通过）、判定与必改项不矛盾、独立性（先写独立结论、之后才看作者自检）、
§1 有机械证据表格、无 8 条禁用证据短语（「和旧版一致」「作者说」「看起来合理」等）、至少一条真问题。

```bash
python scripts/check_review_form.py 复核单.md
```

退出码：`0` 合规 / `1` 有缺陷 / `2` 文件读不了。
**证明力上限（必须知道）**：它校验的是**留痕**不是**行为**——两次抄同一段哈希、写一条无关痛痒的问题都能过；
独立性与机械证据表同样只是留痕判据：正文里自认“先看了作者自检”也拦不住（它只看有没有那句限定语），证据表两行只要各带一个路径或行号就算数。模板痕迹只按**行首形态**识别：标题；**把行首的 `>`、`（`/`(`、列表符号（`-`/`*`/`+`）、强调符（`*`/`_`/反引号/引号）循环剥干净后，以「模板/必填/示例/说明/要求/提示」开头**的行。所以 `> **提示**：…`、`> - 提示：…`、`（**提示**）` 这些叠加写法也认得出。只看行首、不看句中——所以「我按要求先写…」这类合法声明不会被误杀；而照着模板骨架填、只把提示行留下的复核单仍会被判缺独立性。它替代不了 Lead 亲自读复核单。

这些脚本**只用标准库**（`check_doc.py` 另需 `python-docx`），路径相对自身或配置文件解析，
**不写死任何本机路径**。

## 项目落地

见 `references/project-scaffold.md`：建 `_team/` 台账、写 `dept.config.json`、写岗位卡、
种子基准清单、接线质量工具、首跑冒烟。换电脑只需拷 `~/.dsh/skills/`。

**新项目一条命令起步**（不用再从别的项目拷台账）：

```bash
python scripts/init_project.py --root <项目根> --desc "<一句话说明>"
python scripts/init_project.py --root <项目根> --open-package "板块 1：<目标>"   # 已经知道第一个板块时
```

生成 `dept.config.json` + `_team/`（章程、工作流、看板、交付登记簿、基准清单、基准变更记录、
三张通用岗位卡、任务单/复核单模板、`bin/` 说明、项目级 `AGENTS.md`）。幂等：**默认不覆盖已存在文件**，
要重写加 `--force`；另有 `--dry-run` / `--json` / `--roles`。
不给 `--open-package` 时，看板「当前板块」留空并写一条 `D0` 待你决定第一个板块——此时闸门 **exit 2**，
这是诚实的：没有板块不许开工（给了 `--open-package` 则 exit 0、零告警）。


## 边界

本 skill **管流程与验收**，不管：
- 专业口径（该用什么模型、什么参数）—— 项目岗位卡与学科 skill；
- 工具实操（怎么跑仿真软件）—— 专用 skill；
- 桌面操作 —— 桌面控制类 skill；
- 实时拦截 —— 宿主的插件/钩子。

## 诚实局限

独立复核能查「这个数算得对不对」，**查不了「这个模型该不该这么建」**。
方法层面的错会被复核放过去。所以 `critical` 档额外要求：方向复盘落纸、基准全部回核、
有明确的人签字，且**不允许用自己的批准替代他人的批准**。

## 多复核人（panel）

单人复核是默认。满足任一**触发条件**时升级为 2–3 人的复核组（成本 ≈ N×单人，按触发召集，不常设）：
产物将当基准被下游引用 / 本主题此前的复核**漏过实质问题** / 用户明确要求 / Lead 可操纵的三处
（组包、简报、抽样）在本包无法用低成本手段缓解。

组成规则：各复核人**锚点方法必须不同**（一个独立重算、一个对外部权威、一个自洽性）——
同一方法的一组人共享同一盲区，人数再多只加成本不加覆盖；可选一名**魔鬼代言人**（简报明确写
「任务是攻击结论」，使「没发现问题」不是合法产出）；**互不可见**（各自先写独立结论，Lead 事后
汇总分歧）；**不共享输入**；名册（谁、用什么方法、哪天）记进看板。判定规则：任一人发现真实
问题即阻断；全票 PASS 仍须 Lead 自己的 L3 探查（critical 档还要人工签核）。

详见 `references/blind-review.md` § Panel review。

**这条机制自己的准入依据（如实记一笔）**：它上线走的是触发条件③「用户明确要求」，
不是①②那种真事故（当时用户判断「多复核人未来会用到、比较有意义、可以防止出大错」）。
按 `references/self-skepticism.md` 准入问 2 的**用户要求例外条款**，这样立项是允许的，但必须
写明依据是"用户要求"而不是编造事故；同一处已写下撤除条件：**若一年内它没有拦到任何真问题，就撤掉**。
上线之后的实证（不是立项时的依据）：它随后两轮共拦下 12 条与 26+9 条问题，其中包含 3 条"照做会出事"，
所以保留"按触发召集、不常设"的形态——成本跟着触发走，用不上就不花。
`references/blind-review.md` 末尾的"高成本缓解手段（脚本化组包 / 禁止 Lead 写简报 /
两级抽样）"仍然只在真事故后才能启用。
